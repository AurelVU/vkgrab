# vkgrab

Кроссплатформенная TUI/CLI-утилита на Python 3 для скачивания медиафайлов,
на которые ссылаются HTML-файлы выгруженного архива ВКонтакте (VK).

Она сканирует `.html`-файлы архива, находит прямые ссылки на фото, аудио и
видеофайлы (в основном на CDN `*.userapi.com` / `*.vk.me`), скачивает каждый
уникальный URL один раз в содержательно-адресуемый кэш, а затем раскладывает
файлы либо рядом с каждым HTML (в папки `<имя>_files/`, как у wget), либо в
одну целевую директорию. Повторный запуск продолжает с места остановки.

Отдельно собираются ссылки на *страницы* видео (`vk.com/vk.ru/video...`,
`youtu.be`, `vkvideo.ru`) — они не являются файлами и скачиваются через
yt-dlp (опционально).

## Установка

Требуется Python >= 3.9.

```bash
# рекомендуется (изолирует окружение)
pipx install .

# или обычный pip
pip install .

# с поддержкой видео через yt-dlp
pipx install '.[video]'        # или: pip install '.[video]'
```

Для разработки (тесты):

```bash
python -m venv .venv
.venv/bin/pip install -e '.[dev]'
.venv/bin/pytest -q
```

## Использование

### TUI (интерактивный режим)

```bash
vkgrab tui
```

Один экран: поле с папкой-источником, выбор режима размещения, галочки типов
медиа, ползунок числа потоков (1–32), поле качества видео для yt-dlp и кнопка
Start/Stop. Далее — фаза сканирования с прогрессом, затем экран загрузки:
общий прогресс-бар, счётчики по типам (найдено/скачано/ошибок/пропущено),
список последних действий воркеров, прокручиваемый лог, скорость и ETA.

Клавиши: `q` — выход, `s` — старт/остановка. Ctrl+C завершает работу штатно,
потоки останавливаются корректно.

### CLI (headless)

```bash
# статистика по ссылкам в архиве (JSON)
vkgrab scan "/path/to/VK Archive"

# скачать всё, разложить рядом с HTML-файлами (папки <имя>_files/)
vkgrab download --src "/path/to/VK Archive"

# скачать только картинки в одну папку
vkgrab download --src "/path/to/VK Archive" \
    --dest-mode single-dir --dest-dir ~/vk_media --types images

# 16 потоков, больше ретраев
vkgrab download --src ... --workers 16 --max-retries 6

# также скачать видео-страницы через yt-dlp (в <src>/videos/)
vkgrab download --src ... --fetch-video-pages --video-quality 'url480/url360/worst'
```

Основные опции `download`:

| Опция | Значение по умолчанию | Описание |
|---|---|---|
| `--src` | `.` | корень архива с `.html`-файлами |
| `--dest-mode` | `next-to-html` | `next-to-html` или `single-dir` |
| `--dest-dir` | `<src>/downloaded_media` | куда класть файлы в режиме `single-dir` |
| `--types` | `all` | `images` / `audio` / `video` / `all` |
| `--workers` | `8` | число потоков загрузки |
| `--max-retries` | `4` | ретраи на URL с экспоненциальной паузой |
| `--fetch-video-pages` | выкл. | скачивать видео-страницы через yt-dlp |
| `--video-quality` | `url360/url240/worst[height<=360]/worst` | селектор форматов yt-dlp `-f` |

## Как работает возобновление (resume)

- Кэш: `<src>/.vkgrab_cache/<md5(url)[:2]>/<md5(url)[2:4]>/<md5(url)>.<ext>` —
  каждый уникальный URL скачивается ровно один раз.
- Манифест: `<src>/.vkgrab_cache/manifest.tsv` (колонки
  `url<TAB>status<TAB>cache_path<TAB>size`) — дописывается только в конец.
  При повторном запуске строки со статусом `ok` пропускаются.
- Загрузка идёт во временный файл рядом с целевым и атомарно переименовывается
  (`os.replace`), поэтому обрыв в середине файла не портит кэш.
- Уже существующие файлы в папках назначения не перезаписываются.
- Ссылки на видео-страницы сохраняются в `<src>/video_page_links.txt`;
  yt-dlp ведёт свой `<src>/videos/download_archive.txt` и не перекачивает
  завершённые ролики. Ошибочные URL — в `failed_urls.txt` /
  `videos/failed.txt`.

## Про видео через yt-dlp

Ссылки вида `vk.com/video...`, `youtu.be/...`, `vkvideo.ru/...` — это страницы,
а не файлы. Для них нужен [yt-dlp](https://github.com/yt-dlp/yt-dlp): либо
команда `yt-dlp` в PATH, либо пакет из extra `video`. vkgrab запускает его как
подпроцесс (`--no-playlist`, архив скачанного, логи в `videos/logs/`, до 5
потоков). Если yt-dlp недоступен — ссылки просто сохраняются в файл.
Для приватного контента можно задать `VK_USER`/`VK_PASS` в окружении.
